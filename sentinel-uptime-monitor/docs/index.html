Uptime monitoring for Discord

Know your site is down before your users do.

Sentinel checks your websites and APIs on a schedule and messages your Discord channel only when something changes. One Python file, no database, no dashboard to host.

    Features

    Quiet when things are fine, clear when they are not

    Everything you need to watch a handful of services, and nothing that needs its own server.

    Alerts

    Smart alerting

    A site must fail several checks in a row before a DOWN alert fires. You get one alert per incident, then a recovery message with the total downtime.

    Speed

    Concurrent checks

    Every site is checked in parallel, with its own timeout, retries and accepted status codes, so a slow site never delays the rest.

    Accuracy

    Content checks

    Require a keyword in the response body. A page that returns 200 but says "maintenance" still counts as down.

    TLS

    Certificate watch

    Get a warning before a certificate expires, once per site, with the number of days left.

    Discord

    Rich embeds

    Alerts show the reason, failed-check count, response time and downtime. Discord rate limits are handled for you.

    Data

    Dashboard-ready output

    Each cycle writes status.json with status, latency, uptime percentage and recent response times.

    Reliability

    Remembers its state

    State survives restarts, so a reboot never re-sends old alerts. Logs rotate automatically.

    CI

    Runs anywhere

    Use --once in a scheduled job. It exits with code 1 when any site is failing.

    Security

    Secrets stay out of code

    The webhook comes from an environment variable, is validated on start-up and is never written to logs.

    How it works

    One alert per incident, not one per failed check

    1. Check

      Each site is requested in parallel. A failure is retried before it counts.

    2. Count

      Failed checks in a row are tracked per site. One blip changes nothing.

    3. Alert once

      When the count reaches failure_threshold, Discord gets a single DOWN message.

    4. Recover

      The first healthy check sends a recovery message with how long the site was down.

    Why it matters. A site that is down for an hour produces exactly two Discord messages: one when it fails and one when it comes back. Your channel stays useful.

    Quick start

    Monitoring in about two minutes

    You need Python 3.10 or newer and a Discord webhook URL.

    Install

    Clone the repository and install the three dependencies.

    terminal
    git clone https://github.com/JudeaTablate/sentinel-uptime-monitor.git
cd sentinel-uptime-monitor
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

    Add your webhook

    Copy the template, then paste your URL into .env. The file is git-ignored.

    .env
    DISCORD_WEBHOOK_URL=# paste your Discord webhook URL here

    Run it

    Send a test alert first, then start monitoring.

    terminal
    python monitor.py --test-alert
python monitor.py

    Keep it running

    /etc/systemd/system/sentinel.service
    [Unit]
Description=Sentinel uptime monitor
After=network-online.target

[Service]
WorkingDirectory=/opt/sentinel
EnvironmentFile=/opt/sentinel/.env
ExecStart=/opt/sentinel/.venv/bin/python monitor.py
Restart=on-failure
User=sentinel

[Install]
WantedBy=multi-user.target
    .github/workflows/monitor.yml
    name: Monitor
on:
  schedule:
    - cron: "*/10 * * * *"
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r requirements.txt
      - run: python monitor.py --once
        env:
          DISCORD_WEBHOOK_URL: ${{ secrets.DISCORD_WEBHOOK_URL }}
    crontab -e
    # every 5 minutes; the exit code is 1 if any site is failing
*/5 * * * * cd /opt/sentinel && .venv/bin/python monitor.py --once

    Configuration

    One YAML file, no secrets in it

    Choose what to watch in config.yaml. The webhook lives in the environment, never here.

    config.yaml
    settings:
  interval: 60            # seconds between cycles
  timeout: 10             # seconds before a request fails
  retries: 1              # extra attempts per check
  failure_threshold: 2    # failures before a DOWN alert
  workers: 8              # sites checked in parallel
  ssl_warn_days: 14       # certificate warning window

sites:
  - name: My API
    url: https://api.example.com/health
    expected_status: [200, 204]
    timeout: 5
    keyword: '"status":"ok"'

    Site options

    OptionWhat it does
    urlRequired. Must start with http:// or https://
    nameLabel used in alerts. Defaults to the host.
    expected_statusAccepted status codes. Default 200.
    timeoutOverrides the global timeout for this site.
    keywordText the response body must contain.

    Command line

    FlagWhat it does
    -c, --configUse another config file.
    --onceRun one cycle, exit 1 if any site fails.
    --test-alertSend a test message and exit.
    -v, --verboseShow debug output.

    Security

    Your webhook never touches the code

    Anyone who holds a Discord webhook URL can post to your channel. Sentinel is built so that URL stays out of your repository.

    Environment only

    The URL is read from DISCORD_WEBHOOK_URL. .env is git-ignored and only an empty .env.example is committed.

    Validated, never logged

    Sentinel refuses anything that is not a real discord.com webhook, and keeps the URL out of logs and error messages.

    Checked on every push

    A guard test and a secret scan in CI fail the build if a webhook-looking URL is ever committed.

    If a webhook leaks

    Deleting it in a new commit is not enough. The value stays in git history and may already have been copied.

    1. Delete it in Discord. Open Server Settings, then Integrations, then Webhooks. Remove the exposed webhook and create a new one.
    2. Store the new URL safely. Put it in your environment or .env, never in source.
    3. Optionally clean history. Tools like git filter-repo can remove the old value. This is housekeeping, since the deleted webhook no longer works.
